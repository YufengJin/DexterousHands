# DexterousHands — Benchmark Guide

Generated by `benchmark-generator` skill. English-only by contract; regenerated on every re-run.

## About

DexterousHands (a.k.a. `bidexhands`) is a benchmark of **bi-manual dexterous manipulation** tasks built on NVIDIA IsaacGym. It ships Shadow Hand and Allegro Hand environments with GPU-parallel physics (thousands of envs in a single process), a shaped reward per task, and reference RL / MARL / Meta-RL / Multi-Task / Offline-RL baselines in the same repository.

| Field | Value |
|-------|-------|
| Simulator | NVIDIA IsaacGym (Preview Release 4, PhysX backend) |
| Benchmark category | **RL** (GPU-parallel vectorised envs with shaped reward, in-tree baselines) |
| Baselines mode | `dispatcher` — `bidexhands/train.py` orchestrates SARL / MARL / MTRL / META / OFFRL families |
| Upstream paper / project | "Bi-DexHands: Towards Human-Level Bimanual Dexterous Manipulation" (PKU-MARL) — https://arxiv.org/abs/2206.08686 |
| License | Apache-2.0 (see `LICENSE` at repo root) |
| Primary use case | Large-scale RL training for bi-manual manipulation policies; benchmark baselines for MARL / Meta-RL / Multi-Task / Offline-RL research |

> **Note**: This is an IsaacGym-based benchmark. It ships its own `bidexhands/train.py` as the native entry point; the generic `scripts/run_demo.py` / `scripts/run_eval.py` / `scripts/train_rl_policy.py` are intentionally absent per the benchmark-generator IsaacGym short-circuit clause.

### Task groups

- **Handoff** (Over / CatchUnderarm / CatchOver2Underarm / TwoCatchUnderarm / CatchAbreast) — coordinated bi-manual object transfer
- **Door** (DoorOpenInward / DoorOpenOutward / DoorCloseInward / DoorCloseOutward) — articulated-object interaction
- **Tool-use** (BottleCap / Kettle / Scissors / SwingCup) — contact-rich manipulation with constrained-DoF objects
- **Pick-and-place** (BlockStack / PushBlock / GraspAndPlace / LiftUnderarm) — classical manipulation primitives
- **Single-hand** (ReOrientation / Pen) — single Shadow Hand tasks
- **Allegro variants** (AllegroHandOver / AllegroHandCatchUnderarm) — same task on a different embodiment

## Action / Observation spaces

| Field | Value |
|-------|-------|
| Action dim | `20` (single Shadow Hand) / `40` (two Shadow Hands) — set by `self.cfg["env"]["numActions"]` per task |
| Action semantics | Joint-position targets for each finger DoF (24 DoF per Shadow Hand with sign-of-life coupling); continuous torque limits applied by the PhysX controller |
| Observation type | Proprioception + object state + goal state (`num_obs_dict` in each task class). Each Shadow Hand contributes 199 dims (DoF position / velocity / force, fingertip pose+vel+force, base pose, last action), plus per-task object/goal state. `ShadowHandPointCloud` additionally exposes a point-cloud variant. |
| Observation dim | 398 (dual hands base) + 24 (object pose / vel / goal pose) for `ShadowHandOver` → 422 typical; tasks that mix more goals (door, kettle) extend further |
| Control frequency | 60 Hz simulation, typically 20 Hz effective control after `controlFrequencyInv=3` |
| Reward signal | Shaped: distance reward + rotation reward + action penalty + success bonus; see `compute_hand_reward` in each task for the exact weighted sum |

## How to use

The skill produced two receipt files at the repo root — `history.md` (what the skill did, overwritten on every re-run) and this file (what the benchmark *is*). `install.md` is owned by `env-generator`. The flow below assumes you have already followed `install.md` and have a running container.

### 1. Enter the container

```bash
docker compose -f docker/docker-compose.headless.yaml up -d
docker exec -it dexteroushands-headless bash
```

### 2. Pick a task

Any identifier from the task table above is a valid value for `--task`. Quickest sanity check:

```bash
# List the canonical task IDs that ship with this benchmark
grep -oE '"ShadowHand[A-Za-z]+"|"AllegroHand[A-Za-z]+"' \
    /workspace/dexteroushands/bidexhands/utils/config.py | sort -u
```

### 3. Train with the benchmark's native entry point

IsaacGym benchmarks have a custom env-construction protocol (argparse + `gymapi` pre-import ordering, `os.getcwd()` config resolver) and ship their own `train.py`. Use it directly rather than a generic `scripts/train_rl_policy.py`:

```bash
# Must run from inside bidexhands/ (train.py uses os.getcwd() to locate cfg/)
cd /workspace/dexteroushands/bidexhands

# Smoke / sanity — 1 iteration with 16 envs, headless
python train.py --task ShadowHandOver --algo ppo --num_envs 16 --headless --max_iterations 1

# Full training — 4096 envs on a single 4090, headless
python train.py --task ShadowHandOver --algo ppo --num_envs 4096 --headless
```

For MARL / Meta-RL / Multi-Task / Offline-RL, use the corresponding entry points (same dispatcher, different `--algo`):

```bash
python train.py --task ShadowHandOver --algo happo     # MARL: happo / mappo / ippo / hatrpo / maddpg
python train.py --task ShadowHandMetaMT1 --algo mamlppo  # Meta-RL
python train.py --task ShadowHandMetaMT4 --algo mtppo  # Multi-Task
python train.py --task ShadowHandOver --algo td3_bc    # Offline-RL: bcq / iql / td3_bc / ppo_collect
```

### 4. Evaluate a checkpoint

```bash
cd /workspace/dexteroushands/bidexhands
python train.py --task ShadowHandOver --algo ppo --num_envs 64 --test \
    --model_dir logs/ShadowHandOver/ppo/ppo/model_<iter>.pt --headless
```

The `--test` flag disables training updates; `--model_dir` points at a checkpoint written during a previous training run.

### 5. Use bidexhands as a Python library

The repo can also be called from your own Python script (since the 2023-02-09 re-package):

```python
# isaacgym MUST be imported before torch
import isaacgym
import bidexhands as bi

env = bi.make(
    "ShadowHandOver",   # task name
    "ppo",              # algorithm
    seed=0,
    num_envs=64,
    headless=True,
)
obs = env.reset()
for _ in range(100):
    action = env.action_space.sample()
    obs, rew, done, info = env.step(action)
```

## Troubleshooting

- **Task name not recognised**: identifiers are case-sensitive CamelCase (e.g. `ShadowHandOver`, not `shadow_hand_over`). The file names under `bidexhands/tasks/` are snake_case but the `--task` flag takes the CamelCase form from `retrieve_cfg`.
- **`Segmentation fault` at end of training (`gym.destroy()`)**: known IsaacGym upstream issue. Training itself completed — check for the final iteration log line before the segfault.
- **`Segmentation fault` at start of training (in `gym.create_sim`)**: the host NVIDIA driver is too new for IsaacGym Preview 4's bundled PhysX. Validated drivers are in the `~535` series; drivers `570+` SIGSEGV on `+++ Using GPU PhysX → GPU Pipeline: enabled`. The bundled `docker/smoke_test.sh` Layer 3 detects this and prints a `[NOTE]` with three workarounds (downgrade host driver to 535.x; migrate to IsaacLab + IsaacSim 4.x; use the container only for non-PhysX paths) — it does NOT count as a smoke FAIL because the CPU PhysX path is functional. To run actual training you must resolve the host driver issue. See this run's `history.md` "2026-05-02 follow-up patch" for full diagnosis.
- **`ImportError: PyTorch was imported before isaacgym modules`**: `isaacgym` MUST be imported before `torch`. Reorder imports — never `import torch` first.
- **`ModuleNotFoundError: isaacgym`**: the sibling `isaacgym/` directory is missing on the host. Re-run `bash docker/setup.sh` or manually place IsaacGym Preview 4 at `<repo_parent>/isaacgym/`.
- **GUI apps fail with `cannot open display`**: you are on the headless compose profile. Switch to `docker-compose.x11.yaml` after `docker compose down`.
- **`cfg/*.yaml not found`**: you launched `train.py` from the wrong directory. It uses `os.getcwd()` to resolve the config path — always `cd bidexhands/` first.
- **Running actual training (post-2026-05-02 patch)**: `docker/smoke_test.sh` no longer invokes `train.py` (the L3 was redefined as `gym.create_sim` health check). To run training, exec into the container and: `cd /workspace/dexteroushands/bidexhands && python train.py --task ShadowHandOver --algo ppo --num_envs 4096 --headless`. This requires GPU PhysX to work — confirm with the smoke L3 GPU subline before launching long jobs.
